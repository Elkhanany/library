# Putting this on GitHub

This is a complete git repository with its history. It has no remote — nothing here has ever
talked to your GitHub account, and no credential of yours has been anywhere near the machine
that built it. Three commands and it is live.

## 1 · Make an empty repo on GitHub

github.com → **New repository**. Name it whatever you like — `newton-to-mtheory` is the obvious
choice. **Do not** tick "Add a README", "Add .gitignore", or "Choose a license"; the repository
must be empty or the first push will be rejected.

Public or private is your call. **GitHub Pages works on a private repository only on a paid
plan** — on the free plan the repo has to be public for the site to be served.

## 2 · Push

From this folder:

```bash
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

It will ask for your username and then a **personal access token** — not your password; GitHub
stopped accepting passwords over HTTPS in 2021. Make one at
**github.com → Settings → Developer settings → Personal access tokens → Tokens (classic) →
Generate new token**, tick the `repo` scope, and paste it when prompted.

(If you already have the GitHub CLI: `gh repo create <repo-name> --public --source=. --push`
does all of the above in one line.)

## 3 · Turn on Pages

In the new repository: **Settings → Pages → Build and deployment**. Set **Source** to
*Deploy from a branch*, then **Branch** to `main` and the folder to **`/docs`**. Save.

The site appears at `https://<your-username>.github.io/<repo-name>/` within a couple of minutes.
The first build is the slow one.

Then edit one line of `README.md` — the `**Read it:**` link near the top — to point at the real
address.

---

## Afterwards

The site is whatever is in `docs/`, so publishing a new chapter is:

```bash
python3 webbuild.py     # regenerate docs/
git add -A && git commit -m "Chapter 3.7" && git push
```

Pages redeploys on its own. `docs/` is committed deliberately rather than built by an Action:
it means the published site is exactly the bytes you last verified locally, rather than whatever
a build server produced, and it means the repo has no CI to break.

## What is where

| | |
|---|---|
| `STATUS.md` | Where the book stands, and how to resume. Read this first. |
| `src/` | The chapters. The only thing you ever edit by hand. |
| `docs/` | The website. Generated by `webbuild.py`. Never edit. |
| `build/` | The offline copy — one self-contained file per chapter, for Dropbox and for reading on a phone with no signal. Generated by `make.py`, not committed, because it is 50 MB of duplicated fonts. |
| `assets/`, `vendor/` | The house style, and KaTeX vendored so nothing loads from the internet. |
| `*.md` in the root | The plan, the conventions, the gaps register. `README.md` says what each is for. |
| `reports/` | The August 2026 review. |

## Rebuilding from scratch

```bash
pip install playwright
playwright install chromium
python3 make.py && python3 webbuild.py && python3 verify.py
```

`verify.py` is the one that matters: it opens every built page at desktop and phone widths **with
all network requests blocked**, and fails if any equation did not typeset, any cross-reference did
not resolve, any maths overflows its column, or any page tries to reach the internet.
